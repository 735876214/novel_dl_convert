## 0. 结论摘要

- **两个产品定位不同**：NovelForge 是「中文网文 / TXT / 电子书 → 书库 + 在线阅读器」的单用户 NAS 工具；
  BookOrbit 是「多用户书籍 / 漫画 / 有声书 / 播客服务器」，带采集管线、设备同步、邮件投递、TTS、
  外部迁移与 i18n。把两者的功能逐项对齐时，必须区分**真缺口 / 定位外 / 红线禁止 / 需取证**四类。
- **阅读与书库主干同量级，本项目局部更强**：阅读器、书库/系列/作者/合集/智能范围、元数据、统计与成就、
  OPDS/KOReader、书源采集都在；本项目额外有在线章节阅读 + 追更、序号单元合集、系列续接、
  KOReader 批注离线导入、回收站/移动回滚/冲突修复/容器展开、Komga v1 兼容、CLI、鸿蒙原生端、
  一键自更新 + 更新前数据库快照。
- **真正的差距集中在四类**：①书目与治理的可表达性（排序/分面/分桶/列面板/批量编辑/重复治理/实体 7 类）；
  ②有声书增强 + 播客整块；③read-along 媒体叠加；④平台形态（PWA / 实时推送 / 全局安全头 / history 路由）。
- **数量**：10 个域共核实 **同/近同 ≈125 条、本项目独有 76 条、上游独有 196 条、同名不同义 108 条**
  （按域条目计，含跨域重复项；附录 A–C 为去重后的全表）。
- **一处真实缺陷**：Book Dock 页四个统计恒为 0（读错字段，见 §7）。
- **本轮已实施 Phase 0**（对照文档 + history 路由 + 安全响应头 + PWA/SW + WebSocket 实时事件 + 修上述缺陷）；
  后续按 §5 的分期推进。

## 1. 取证方法与边界

### 1.1 两方证据

| 方 | 证据 | 数量 | 采集方式 |
|---|---|---|---|
| BookOrbit（线上） | `/api/v1/...` 路径 | 320 | 从前端 chunk 抽取 |
| | 组件 / 页面 chunk 名 | 472（含 42 个设置页） | `index.html` + 懒加载 chunk 引用递归下载 |
| | 英文 UI 文案 | 13 个命名空间，约 500 KB | `en-*.js` 内 13 个 `JSON.parse` 块 |
| | 运行时探活 | 少量 | 仅未鉴权端点：`/api/v1/health`、`/api/v1/auth/login-options`、`/api/v1/auth/setup-status`、`/manifest.webmanifest`、`/sw.js` |
| NovelForge（本地） | 后端路由 | 346 | `server.py` 的 `@app.*` 装饰器 |
| | core 模块 | 76 | `novelforge/core/*.py` |
| | 前端页面 / 设置页 | 24 / 37 | `views/*.vue`、`settingsNav.ts` |
| | 其他消费方 | 鸿蒙端、CLI、OPDS/Komga/KOReader | `clients/harmony`、`cli.py`、协议模块 |

### 1.2 证据强度（每条结论的实际依据）

- **代码 + 契约**：两侧都能落到源码/路由/用例（最强）。
- **i18n + chunk**：上游侧只有 UI 文案与组件名，能证明「界面上有这个功能」，不能证明后端行为细节。
- **仅端点缺失**：上游抽取样本里没出现某条路径。**只能写「样本里未出现」，不能写「不存在」**——
  上游有动态拼接 URL（例如 move 的路径就是拼出来的）。
- **运行时实测**：只有未鉴权的少数端点。**实例的代码能力 ≠ 本实例已开启**：
  例如 `login-options` 返回 `oidcProviders: []`、`allowRegistration: false`，
  只能证明「这个实例没开」，不能证明「上游没有这套代码」。

### 1.3 已知限制

1. 未登录，所有「上游行为」来自前端 bundle 的静态证据；语义细节（如定稿流程）是**推断**，
   已在下文逐条标注「推断」。
2. **「同/近同」条目没有逐条做对抗性核查**（核查集中在「缺失」与「同名不同义」）；
   §3 的 same 列表按「行为等价」保守收录，发现同名不同义时已移到差异条目。
3. 本地 `server.py` 有并行会话的未提交改动，**行号会漂移**；本文一律用**路由字符串 / 符号名 /
   i18n key** 作锚点，不用裸行号。
4. 上游版本号未在不鉴权接口暴露；以构建产物 `last-modified: 2026-10-20` 为版本标识。
5. **10 个域全部做过一次对抗性核查**（catalog / metadata 两域在首轮 agent 失败后单独重跑）。
   元数据域 33 条结论：23 confirmed / 10 partial / 0 refuted；partial 已回写到 §3.3 与
   附录 A/B 的读表须知（例如「批量抓取有失败列表与按库开关」其实已存在，缺的是 pause/resume/cancel
   与 preview-breakdown）。

## 2. 总体判断

### 2.1 相同/近同的主干

- **书库与书目**：库 CRUD 与每库设置、扫描、书目详情（元数据/文件/目录/音频/单元）、私人书评、
  相似书推荐、系列/作者详情、快速预览、自定义字段、元数据编辑 + 字段锁 + 撤回、
  合集/智能范围 CRUD、统计概览。
- **收书链路**：投递目录 + 五状态页签、上传、单条重扫、丢弃、暂停/恢复、自动抓元数据 + 置信度定稿、
  扫描规则（格式白名单/排除）、路径浏览器、重复书、缺失资源、跨库移动。
- **元数据**：13 家提供商、在线候选、单书编辑 + 锁 + 撤回、自定义字段、字段规则、类型黑名单、
  入库自动抓取与阈值、评分、作者简介/头像/批量抓取、提供商体检。
- **阅读器**：eBook 全量排版、13 档主题、字体库、固定版式、目录、书签、高亮/笔记、批注总览
  （垃圾桶/导出/恢复）、进度/会话/重读轮次/多设备冲突、偏好同步、PDF 四种排布 + 双页 + 缩放、
  CBZ 全套、有声书播放器、个人书评。
- **统计/成就**：30 张统计图、元数据评分分布、成就总览/重算/开关、单书阅读日志、手工补录、
  热力图、通知中心（未读/已读/全部已读）。
- **集成**：OPDS 只读目录、KOReader kosync 进度、Hardcover、Readwise、StoryGraph Cookie。
- **采集**：书源台账 + 启停、单源测试、跨源检索 + 逐源失败、出网总闸、凭据只回状态、私网放行、
  单源超时、端到端入库、任务进度。
- **平台**：登录/改密/头像/展示名/时区/主题/成就开关/审计/引导/更新日志/默认口令提示。

## 3. 逐域对照

### 3.1 书库 / 书目 / 系列作者 / 合集 / 智能范围 / 浏览（catalog）

**上游独有（19）**：合集/智能范围/书库手动排序；书库访问控制；向指定书库上传；书库概览；

写回书文件。

**同名不同义（16）**：合集成员排序、智能范围表达力与求值位置、书目筛选与 DB 侧分页、

### 3.2 收书 / 导入 / Book Dock / 扫描 / 迁移（ingestion）

**上游独有（16）**：入库文件名预览、封面预览、手动定稿、定稿前查重、抓取/重试/应用元数据、
批量编辑、每库扫描历史、按库刷新封面、书库直传上传、路径浏览器内新建文件夹、一次性迁移、

**决定**：前九项做（Phase 4）；迁移只做「只读登记」导入；所有清理走回收站。

### 3.3 元数据 / 缓存 / 评分 / 自定义字段 / 作者增强（metadata）

`metadata/revert`，不新开端点。

### 3.4 阅读器（EPUB / PDF / CBZ / 有声书）/ 批注书签 / TTS（reader）

### 3.11 跨域：平台形态与架构

| 维度 | BookOrbit | NovelForge（本轮前） | 本轮决定 |
|---|---|---|---|
| PWA | manifest + SW（Workbox 预缓存）+ apple-touch-icon | 无 manifest、无 SW | **已做**：manifest + 图标 + SW（导航 network-first、assets cache-first、不缓存 API） |
| 实时更新 | Socket.IO 推送（book-dock / progress / metadata-fetch / cover / author / requests） | 轮询 | **已做**：Starlette WebSocket + 进程内事件总线；事件名对齐；前端断线重连 + 轮询兜底 |

| i18n | vue-i18n + 语言选择 | 中文单语 | 不做 |

## 4. 跨域裁决（本轮已定）

多域对照里出现过互相打架的建议；按用户 2026-10-26 的决定统一如下：

| 问题 | 统一结论 |
|---|---|
| 写回书文件 | **跳过**。数据只落服务端 DB；源文件与库内成品都不写 |
| 批量文件重命名 | 只改 `OUTPUT_DIR` 受管副本（预览 + `remap_book_id` + 冲突拒绝）；收书目录原件不动 |
| 书库访问控制 | 不引入多用户；做 **OPDS / Komga 只读凭据**（可禁用/轮换）+ 逐库 expose |
| 邮件投递（SMTP→Kindle） | 不做 |
| added-at | 做；**一张覆盖表/一列 + 一次重算**，不要三种口径 |
| 每库扫描历史 | 做；**一张表**（库/触发源/起止/新增·更新·缺失/耗时/失败），`last_scan_at` 做成投影 |
| 有声书书签 | 复用 `bookmarks` 表，把 `audio:<track>:<sec>` 编进 `anchor`；不加 locator 列 |
| 书库直传上传 | 加已鉴权的 `POST /api/book-dock/upload`，目标校验复用 `bookdock._ingest_target`；不给 `/convert` 加目标参数 |
| 重复书作业化 | 先补 hash/ISBN 判据 + `duplicates_dismissals`；后台作业按规模阈值后置 |
| 通知偏好落点 | 并入 `prefs` payload（`server.PREFS_BLOCKS` ↔ `lib/prefsPayload.ts`），不另建用户设置表 |
| 外部书库迁移 | 只做「只读登记」导入（Calibre `metadata.db` / 书库目录）；完整迁移 UI 不做 |
| 实时推送 | 做 WebSocket；事件只推「该刷新了」，HTTP 仍是唯一真值源；断线回退轮询 |

## 7. 本次发现的缺陷与安全项

### 7.1 已修（Phase 0）

- **Book Dock 四项统计恒 0**：`BookDockPage.vue` 读 `watcher.converted/added/failed/scans`，
  而 `/api/watcher` 的 `status()` 把计数放在 `stats` 下。已改为读 `watcher.stats.*`，
  并加 spec 断言非 0。

### 7.2 待决策（不在 Phase 0）

- **旧接口的可选鉴权**：`/convert`、`/convert-path`、`/download/{name:path}` 历史上只做
  「带了 token 就记录操作者」，不强制鉴权（`/content` 已于第 97 期删除并钉 404）。
  NAS 暴露到局域网时这是一个真实面；需要决定：加开关 / 限制来源 IP / 直接纳入鉴权
  （会破坏油猴脚本等历史用法）。
- **`GET /api/achievements` 会写库**（顺带解锁），`backfill` 会重置解锁时间 —— REST 语义缺陷，
  建议拆成「只读评估」+ 显式「重算」。
- **通用整库备份**：目前数据库快照只发生在自更新前；是否需要「随时备份/恢复」入口。
- **PDF 文字层注释与代码不一致**：`comicPrefs.ts` 注释称 PDF 可保留文字选择与搜索，
  实际 `PdfReader.vue` 只画 canvas —— 做 PDF 批注前必须先补文字层。
- **作者抓取开关是「死配置」**：`metadata_fetch.authors.fetch_bio / fetch_photo / sources`
  在 `MetadataPage.vue` 有开关，但后端 `core/authors.py` 没有任何读点 —— 点了不改变行为
  （违反「不做假交互」）。修法二选一：把开关接进 `authors.fetch_author`，或删掉这三个 UI 开关。
