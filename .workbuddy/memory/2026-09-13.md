# 2026-09-13

## Dockerfile 改为多阶段构建（CI/CD 优化）

- 背景：镜像由 GitHub Actions 推到 ghcr.io，NAS 直接 `docker compose up -d` 拉取；
  旧 Dockerfile 是单阶段 `python:3.12-slim + apt install nodejs + pip install`，偏大。
- 新结构三阶段：
  - `builder`：`build-essential` + venv `/opt/venv`（编译链不进最终镜像，arm64 无 wheel 时可兜底编译）
  - `nodejs`：`node:22-bookworm-slim`，只 COPY `/usr/local/bin/node`（与 python:3.12-slim 同为 bookworm，glibc 一致）
  - `runtime`：`python:3.12-slim` + venv + 源码，只装 `tzdata`(让 TZ 生效) 与 `libstdc++6`(node 依赖)
- 瘦身动作：venv 删 pip/wheel、`.so` 去符号、按路径精确 COPY 配 `.dockerignore`、
  全程 `--no-cache-dir`。刻意保留 setuptools/pkg_resources（运行时可能被 import，本机无 Docker 无法验证）。
- 联动改动：
  - `start.sh` 去掉运行时 apt/pip 安装分支（依赖已内置，且 venv 里已无 pip）→ 仅自检 + exec uvicorn
  - CI 加 QEMU/buildx，多架构 `linux/amd64,linux/arm64`，`provenance:false`（老版 Docker 拉多架构镜像会解析异常），加 GHA 层缓存
  - `.dockerignore` 补全：`.github`、`cookies/`、`cache/`、`docker-compose.yml`、`.env*` 等

## 约定 / 环境事实

- 本机无 Docker CLI，无法本地 build 验证；**靠 GitHub Actions 的构建结果当验证手段**
  （`GET /repos/{owner}/{repo}/actions/runs?per_page=1`）。
- 本机 git 推送被代理拦截（`CONNECT tunnel failed 502`），`github-push-via-api` skill 可用；
  本次踩坑：远端 tip 会移动（需现取 ref + `compare` 核对）、blob 内容必须用
  `git cat-file blob`（工作区 CRLF 与对象库 LF 不一致会导致 sha 不匹配）。已回写进该 skill。
- 该仓库存在「工作区文件已是远端最新内容、但未提交」的情况，提交前先
  `git diff FETCH_HEAD --stat` 判断真实差异，别只看 `git status`（会显示一堆历史遗留的"已修改"）。
