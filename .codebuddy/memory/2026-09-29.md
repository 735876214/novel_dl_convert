## 第 73 期：漫画 / 有声书库的「序号单元」合并成书 + 连续阅读

### 缘起（用户原话要点）
漫画库 / 有声书库里一本书的实际形态是 `根目录/《转生魔女宣告毁灭（1-43话）》/若干级文件夹/第1话.pdf`，
文件名序号写法不统一（`第1话` / `第二话` / `第03话` / `4 第4话`），而扫描层是「一个文件 = 一本书」
⇒ 书架上 43 本各自独立的书（书名就是 `第1话`），既看不出同属一本，也读不成连续的话；
`_iter_book_entries` 那句「只下探一层」还让更深的文件**根本扫不到**。
需求两条：① 书库层整棵树 = 一本书、书名《转生魔女宣告毁灭》；② 阅读层逐话连续读。
用户拍板四条：合并判据 = 序号单元判据 / 只管漫画库 + 有声书库 / 合并 + 连续阅读 / 窄规则剥书名备注。

### 一、判据本体：`novelforge/core/units.py`（新增 495 行）
- **「一棵树 = 一本书」的唯一真值源**：`is_unit_dir` = 递归枚举媒体文件后，**≥2 个能解析出序号、
  且序号不全相同**。两道闸各有各的用：「≥2」排除只有一话的目录；「不全相同」排除**把容器当书**
  （`作者/《甲》/第1话.cbz` + `作者/《乙》/第1话.cbz` 两个文件都解析得出序号，但那是两本书各自的第一话）。
  **宁可少合并**（退回今天的行为）**不可错合并**（用户只能靠改名目录救）。
- `parse_unit` 三形态（标记必须在**开头**）：`第12话` / `第十二話` / `第03卷`（标记后可带标题）、
  `4 第4话`（前缀数字**等于**单元号）、`01` / `007`（纯数字，`≤ _MAX_UNIT = 999`）。
  **刻意不收**：`《甲》(第1卷).cbz`（标记不在开头）、`作品名 第1话.pdf`、`第1-43话.pdf`（那是范围）、
  `4x 第4话.pdf`、`2024.pdf`（裸数字超界）、`vol.1.cbz`。
- 排序 `(序号, 自然序)`，**解析不出序号的排最后**（`序章` / `番外` 不猜位置）；`name` 是**相对树根**的
  posix 路径（要直接下发前端，不含绝对路径）。
- 上限 `_MAX_DEPTH = 4` / `_MAX_FILES = 5000`，**超限一律不合并**（保守退回；符号链接环路靠深度兜住）。
- **两套 exts 口径是有意的**：枚举侧按**库生效白名单**判，探测侧（`_probe_entry` 只能依赖文件自身）
  用固定 `UNIT_EXTS` —— 同一份实现、两个配置。
- **库级排除图案（`exclude`）刻意不在树内应用**：一棵通过判据的树整棵就是一个条目，图案作用的对象
  已经消失；更要紧的是**增量闸门拿不到图案**（`_cheap_facts` 只有路径）—— 应用了就会出现
  「卡片说 4 话、阅读器里 5 话」。
- 三处同源收敛：`shape_of`（**先平铺音频、后序号单元** —— 编号轨有声书 `01.mp3…12.mp3` 同时满足
  两条判据，取音频形态才能让「N 轨 + 播放器」这套既有行为逐字不变）、`collected_by`（枚举与
  **搬家闸门**同读）、`merges_for`（只认 `comic` / `audiobook`）。
- ⚠️ **与 `komga.infer` 是两套判据，刻意不合并**：那套解析「系列名 + 册号」、要 ≥2 字的系列名，
  实测对 `第1话` / `4 第4话` / `01` 一律返回空。

### 二、扫描层 + 口径自愈 + 搬家同源（`library.py` / `catalog.py` / `migrate.py`）
- `_iter_book_entries` 加 `ltype` 形参 + 一支新分支（在「顶层文件 → 隐藏目录 → 音频目录」之后、
  下探一层之前），命中即 `continue`（书边界 = **最外层**，不 `continue` 会把子树文件当兄弟条目重登记）。
- `_probe_entry`：`tracks = 话数`（**复用既有的 `tracks` 列** ⇒ 零新列零迁移）、`format = AUDIO`（全音频话）
  / `UNITS`、`pages = 0`；**签名不变**。
- `_cheap_facts` 目录分支改 `units.dir_fingerprint`（**递归**）—— **本期唯一的性能代价**（目录型条目
  从一次 scandir 变成一次递归遍历，带 `_MAX_FILES` 上限）。指纹必须看得见树里**每一个**文件
  （含封面），只算媒体文件的话「加一张封面」在增量闸门上完全看不见。
- **`SCAN_RULE_VERSION = 1`**（`library.py`）：凡改变「条目边界或卡片字段口径」的改动都要 +1。
  `catalog` 把它**按库**记在 `app_state`（`book_index_rule:{lid}`），不一致 ⇒ 该库下一轮刷新**当作 force**。
  ⚠️ **按库分键是必须的**：记成全局的话第一个刷新完的库会写上新版本，**后面的库再也不重探**
  ⇒ 只有一本书被修好，比不修更难查。这是**存量索引唯一的自愈通道**（磁盘没变 ⇒ `(size, mtime)`
  闸门永不重探旧行；第 72 期在派生件那边踩过同一个坑）。
- 排序同源：`catalog` 里「精确复刻遍历顺序」的排序键同批改（否则书架顺序抖动）；
  搬家同源：`migrate` 里第三份「是不是音频目录」字面量收敛到 `collected_by`。

### 三、书名剥掉「范围 / 话数备注」（`metadata.strip_count_note`）
尾部括号、两种形状：`第?全?\d*(?:[-–~]\d+)[话話卷回册集部篇幕章]?` 与 `全?\d+[话話卷回册集部篇幕章]`。
⇒ `（1-43话）`/`（全43话）`/`（第1-43话）`/`（1-43）` 剥；**反例不剥** `（0079）`/`（修订版）`/`（上册）`。
`from_filename` 的**两个分支**都过它 ⇒ 对所有书生效（含存量，靠口径版本自愈重探）；用户改过的书名在
覆盖层里、优先 ⇒ 不覆盖用户编辑。

### 五、前端：合集阅读器 + 进度换算唯一真值源
- **新增 `lib/unitsProgress.ts`**：`toPercent` / `fromPercent` 是「话 / 轨 ↔ 百分比」的唯一真值源
  （口径与改造前 `AudioPlayer` 逐字相同），顺手把 `AudioPlayer` 里那份
  `Math.floor(percent / 100 * total)` 的**第二份反推公式**收敛掉。
- ⚠️ **单测当场抓到一个静默错话的真缺陷**：`toPercent(i, 0, total)` 写出去的是 `i / total × 100`，
  乘回来在二进制浮点下**不严格互逆** —— 43 话的书里第 16 话的开头反解成 `15.999999999999998`，
  `floor` 后落到**第 15 话的末尾**（界面显示第 16 话，重开回到第 15 话最后一页，**不报错**）。
  修法：`fromPercent` 加 `BOUNDARY_EPS = 1e-9`；往返用例改成「话号**精确** + 话内比例只要浮点容差」。
- **新增 `components/reader/UnitsReader.vue`**：话目录 + 上/下一话 + 「N / M」+ 形态徽章；主区按
  `kind` 挂 `PdfReader` / `ComicReader` / `AudioPlayer`（`:key` = 话号 ⇒ 换话**重建**）。
- **进度由上层独占**（最容易写错、又完全看不出来的地方）：整本书只有 `progress` 那一行 `percent`，
  `UnitsReader` 是**唯一**写它的地方；三个子阅读器进入**单话模式**（`unit` ⇒ 数据源换 `/units/{index}`、
  进度不读不写、只上报 `unitPos` / `unitEnd`）。四条协议：
  ① 上报带 `index` ⇒ **丢弃过期上报**（换话时旧组件卸载还会再报一次，不核对会把「第 3 话读到一半」
  写成「第 4 话读到一半」）；② 换话两笔写入**串行**；③ 卸载时**补写**；④ 写库**不取整**。
  `UnitsReader.spec.ts` 9 例钉住这套协议（含「自动续话的音频 autoplay、用户点下一话不自动播」）。
- 分流与展示：`ReaderView.isUnits`、`bookInfo` UNITS → 「合集」/「N 话」、`bookOpen` 两个格式集纳入 UNITS、
  `BookDetailView.canRead` 纳入（判据是有没有话）、目录型条目 `canDownload = !isDirEntry`。

### 踩坑 / 经验
- ⚠️ **`await router.isReady()` 不能写在 `mount` 之前**：首次导航由 `app.use(router)`（即 mount）发起，
  先 await 它就是**死等** —— 表现是**每个用例都 5s 超时**（本会话实测 9 例一起超时）。
- ⚠️ **`vue-tsc` 对桩的联合类型按名字取 prop 会收成 `never`** ⇒ 用例改成 `.props()` 整取再断言；
  另外**桩用 `h()` 不用 `template:`**（运行期模板编译要完整版 Vue，vitest 走的是 bundler 版）。
- ⚠️ **在 ASCII 框图里改字要按字符宽度补齐**：`docs/architecture.md` 是 **CRLF**，且在 heredoc 里写
  `·` 等字符会被 shell 弄坏 ⇒ 用脚本**从文件自身**取分隔符、只插一个词再按差额扣尾部填充，
  并断言行长不变（本轮前两次手算全错，第三次才成）。
- ⚠️ **验收用的「反向」预期要实测**：计划写「同一棵树放进 ebook 库仍是 4 本」，实测**深一层是 0 本**
  （既有「只下探一层」边界，非本期回归），**浅一层才是 4 本**。两个方向都跑了才敢下结论。
- ⚠️ **API 侧 `publish_path` 有「不得与库根重叠」守卫**，本容器唯一来源根被测试库占满 ⇒
  发布回归只能**容器内直调原语**（如实标注：不是走 API 发布的）。
- 活动日志 `status` 取值是中文「成功 / 失败」，用英文过滤会把**全部**条目都当异常（差点误报）。
