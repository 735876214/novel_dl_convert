### C. 隐形文件防护：实际行为是 fall-through 改判，不是「一起拒收」

`library_rules.decide` 的候选过滤跳过「收了也看不见」的库（判据 = `library.accepts_ext`）
⇒ 返回 `None` 走**既有拒收路径**。⚠️ 但**只有当所有候选库都看不见它时才拒收**；
仍有别的库收得了，就**改判到那一个**。选型时「一起拒收」的措辞与实际行为有差，如实记。

这是**既有问题**（`type=ebook` 的库把 `source_subdir` 指向漫画目录，今天就能造出
「文件落了盘、书目里却没有」），`allowed_exts` 可配之后撞上的概率大幅提高。
跨库移动的相容闸门（`migrate.py`）同样改判**目标库**的生效格式集。

### D. 库级排除图案与 `watcher.ignore` **刻意有两处差异**

① `fnmatch.fnmatchcase`（平台无关）—— `watcher._ignored` 用的 `fnmatch.fnmatch`
在 Windows 上**大小写不敏感**，而库级排除是用户显式写下的规则，不能随平台变；
② 图案含 `/` 时匹**相对库根**的路径，否则只匹 basename（watcher 那套是纯 basename）。
`watcher.ignore` 本期**一行不改**：它的作用域是 `INPUT_DIR`，与库扫描是两条轴。
⇒ 若哪天被改回 `fnmatch` / 纯 basename，**Linux 上照样全绿**，只有 Windows 那条大小写用例会红
（`tests/test_library_scan_scope.py::test_图案大小写敏感`）。

### G. 三个坑

1. ⚠️ **Git Bash 的 `/tmp` 与 Python 看到的 `/tmp` 不是同一个目录。** 前者是
   `%LOCALAPPDATA%\Temp`，后者（原生 Windows 版）解析成 `C:\tmp`。
   `pytest --junitxml=/tmp/x.xml` 之后 bash 里 `ls` 找得到、Python 里 `open()` 报
   `FileNotFoundError`。判据：先 `cygpath -w /tmp/...`，或直接给 Windows 原生绝对路径。
2. `-q` 会加成 `-qq` 吞掉汇总行（第 39 期已记，本轮又踩一次）—— 计数一律走 `--junitxml`。
3. 中文用例名在 GBK 控制台下显示成乱码，`FAILED ...::test_????` 看不出是哪个 ——
   抓失败详情时给 `PYTHONIOENCODING=utf-8`，或统一落 UTF-8 文件再读。

## 第 41 期（续）· 书库存放改造：多来源根 `source_dirs`、移除 import 模式（已完成）

**做了什么**：库数据模型从「单 `root_path` + `source_subdir` + `mode(inplace/import)`」改为「多个文件夹绝对路径 `source_dirs` 数组，仅就地引用」。compose 用 `LIBRARY_SOURCE_DIRS1..N`(+`_NAME`) 声明不定数量来源根，`config.LIBRARY_SOURCE_ROOTS` 仅用于向导浏览树 + 建库时一次性边界校验（`normalize_source_dirs` 拒非来源根内的路径），后端不反查相对子目录。

**两个真实 bug（本轮定位并修复，均会让测试静默失败）**：
