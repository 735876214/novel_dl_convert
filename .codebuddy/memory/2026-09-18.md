## 环境/网络约束（重要）
- 本机**无外网**：Docker Hub（auth.docker.io）与 ghcr 拉取均超时（DeadlineExceeded）。`docker-compose.test.yml` 是本地 build（FROM node:22-bookworm-slim），基础镜像不在本地缓存，**断网环境无法构建**，勿用 `--build` 启动它。
- 本地仅缓存 `ghcr.io/735876214/novel_dl_convert:latest`（真实版镜像，464MB）。
- **「Failed to fetch」根因**：测试/真实容器都没在跑（docker ps -a 空），前端页面加载后所有 `/api` 请求连不上 → 报 Failed to fetch。非前端代码 bug。
- 离线启动真实版镜像的临时方案：新增 `docker-compose.override.yml`（`pull_policy: never` + 端口改 8993 + 挂载 `./novelforge:/app/novelforge`），用 `docker compose -f docker-compose.yml -f docker-compose.override.yml up -d` 启动。复用缓存镜像、挂上 host 的 `novelforge/static/v2`（含最新前端），后端同源可登录（admin/changeme）。**联网恢复后删除该 override 文件即可回归正常流程。**
- 真实版 compose 自带 `pull_policy: always`，离线直接 `docker compose up` 会拉取失败；必须用 override 关掉或改用 `docker run` 指定本地镜像。
