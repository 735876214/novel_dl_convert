### 关键设计决定：**展开成真正的书**，而不是让阅读链路去认容器

「`.zip` 里含 EPUB/PDF 就按对应格式读」有两条路：
① 让 `/file`、`/cover`、`/asset`、章节解析等一串路由都学会「书可能是个容器里的条目」；
② 把容器**展开**成真正的 `.epub` / `.pdf` / 内层压缩包。

选了 ②：①要让十几处路由各自记得判容器（必然漂移，而且每一处漏判都是一次静默失败）；
②之后**既有链路一个字都不用改**。三种情形（判据全在 `core/zipkind.py`）：
容器本身就是改了后缀的 EPUB ⇒ **整份另存为 `.epub`**（EPUB 即 zip，字节复制）；
容器内是文档 ⇒ 逐个提取；容器内是压缩包（嵌套）⇒ 提取内层压缩包（一层一层来）。

三条纪律（写进代码注释与测试）：只在容器所在目录落新文件；**原子写**（`.part` → replace）；
**绝不覆盖已有文件**（撞名逐条如实报，不静默改名 —— 改名会换 `book_id`）；
**默认不删源**（`remove_source=true` 才删，删除不可逆 ⇒ 默认必须最保守）。
另有 **zip-slip 防护**：条目名含 `..` / 绝对路径 / 盘符一律拒绝落盘。

## ⚠️ 本轮重复踩到的坑（下次先看这里）

1. **Python `bytes` 字面量只能是 ASCII** —— 本轮**踩了两次**（`b"这不是压缩包"`、
   `b"原来的"`），两次都是「收集期 SyntaxError」而非断言失败。中文一律
   `"...".encode("utf-8")` 或直接用 ASCII 标记字节（`b"OLD"` / `b"NEW"`）。
2. **会话临时根可能还没建出来** —— 往 `default_root` 写文件前必须
   `default_root.mkdir(parents=True, exist_ok=True)`（本轮踩了三次）。
3. **`apiErrorMessage(e)` 是两参数**，单参调用会被 `vue-tsc` 拦（`TS2554`）；
   页面里自己写个 `msg(e)` 小助手更省事。
4. **`plan_create` 工具整晚返回 `AI_APICallError-Bad Request`**（缩到 700 字的最小版本
   也一样）⇒ 是 planning 服务端故障，不是内容问题。计划改用待办清单承载。
5. **`tests/test_db_concurrency_contract.py::test_锁是重入锁` 偶发红**：单跑必过、
   重跑全量也过 ⇒ 时序敏感的既有测试，不是改动引入的（本轮第一次全量跑就撞上过）。
6. **前端改动必须 `npx vue-tsc --noEmit -p tsconfig.app.json` 再 `npm run build &&
   npm run deploy`**（deploy 把 dist 同步到 `novelforge/static/v2`，服务端发的是它）。
7. **长提交信息不要用 `-m` 多行**（PowerShell 会把参数吃坏、报
   `fatal: '/' is outside repository`）⇒ 用 `[IO.File]::WriteAllLines($f,$m)` 写临时文件 +
   `git commit -F $f`。另外不带 `| Out-Null` 的长命令偶被当成监听指令而**不执行**（要复查）。
