## 第 3 期收官：偏好模式与设备同步（用户需求「阅读偏好设置不同模式」）

### 需求（三轮澄清后的结论）
- 语义：**模式 = 整套偏好的具名快照**（eBook 排版含 13 档主题与字体 / PDF / 漫画 / 应用主题·点缀色·圆角 / 书封）；**设备各自持有配置**；应用模式 = **拷贝**，之后各改各的 → 用户举例：A 做模式一，B 可套用或自己另存模式二，C 可选已有或自建模式三
- 用户选择：服务端**按设备分别存 + 设备列表**；同步范围 = **阅读偏好 + 外观**（不含书架/仪表盘/通知偏好）；保存交互 = **显式**（「保存到当前模式」/「另存为新模式…」）；离线 = **降级本机、恢复后推送**

### 后端
- 两表：`pref_profiles(id,name,payload,created_at,updated_at)`、`pref_devices(id TEXT PK,name,payload,active_profile_id,created_at,last_seen)`
- 9 接口：`/api/prefs/profiles` GET/POST/PUT/DELETE、`/api/prefs/devices` GET、`/{id}` GET/PUT/DELETE、`/{id}/apply/{pid}` POST
- **payload 只做浅校验**（顶层块名白名单 + 每块为对象 + 64KB 上限）——刻意不做字段级深校验：偏好字段随功能演进，深校验会把两端耦死
- `upsert_device` 的 `active_profile_id` 用**哨兵 `_KEEP`** 区分「不传=保留」与「传 None=清空」（推送配置时不该顺手清掉来源标记）
- **删模式只把引用设备的 active_profile_id 置空**（`detached_devices` 回报受影响数），设备 payload 绝不动
- 设备上报**不写活动日志**（每次启动都发生、无审计价值），只有模式变更写（新增 `ACTION_PREFS="偏好"`）

## KOReader 进度互通完成（第 4 期第 3 项）

### 三个必须精确的协议细节（都查了权威源码，别凭记忆改）
1. **鉴权头是 `x-auth-user` / `x-auth-key`**，不是 HTTP Basic；`x-auth-key` = **密码的 MD5**（客户端算好再发）。因此服务端**只存这个哈希**（`koreader.key`），从不接触明文 —— 万一索引泄露也拿不到口令
2. **文档标识是 partialMD5，不是整文件 MD5**（摘自 KOReader `frontend/util.lua`）：
   `step=size=1024`，`for i = -1..10: seek(1024 * 4^i); update(read(1024))` —— 12 个采样点
   （偏移 256/1024/4096/…/1073741824）。**两个易错点：不读文件第 0 字节（首个采样在 256）；读不满 1024 字节（到 EOF）就立即停止采样**，不是继续往后跳。
   动机：KOReader 给 PDF 加高亮会往文件尾部追加数据，采样越靠后越稀疏以降低摘要变化概率。
   另有 `checksum_method=FILENAME` 变体 = `md5(basename)`，**两种口径都索引**（`doc_md5` + `alt_md5`）
3. **进度**：`percentage` 是 0–1；`progress` 对 EPUB 是 XPointer（`/body/DocFragment[20]/body/p[22]/img.0`），对 PDF/漫画是页码字符串

### 客户端行为（据 kosync 插件源码，决定了服务端怎么答）
- `register` / `authorize`：只要 **2xx** 就算成功（失败读 `body.message`）→ 所以 `users/create` 对正确凭据返回 **201**、否则 **402**
- `PUT /syncs/progress`：**401 是唯一被识别的鉴权失败**（且不入重试队列）→ 未启用一律 404，未设密钥用 401
- `GET /syncs/progress/{doc}`：读 `percentage/progress/device/device_id/timestamp`；无 `percentage` 即提示「No progress found」；**`timestamp` 用于与本机翻页时间比新旧**（缺了会退回「百分比更大者胜」的旧逻辑）

### 进度映射
NF 的 `progress(book_id, locator, percent)`：**EPUB 的 locator = 章节 index（0 起）、PDF/漫画 = 页码-1**（前端 `ReaderView.vue:572` 的 `f.index === p.locator`、`PdfReader/ComicReader` 的 `(p.locator||0)+1` 可证）。
- KOReader → NF：`DocFragment[N]` → `locator = N-1`；`percent = percentage × 100`；页码型 `progress` 直接减一
- NF → KOReader：`make_xpointer(locator)`（**只定位到章首的近似值**，准确位置由 `percentage` 兜底，客户端不会因此跳错）；PDF/漫画输出页码
- 自建 `koreader_docs(book_id, doc_md5, alt_md5, size, mtime, computed_at)` 映射表；扫描**整表重建**（幂等，且不会留下指向已删书的陈旧行）

### 交付
`core/koreader.py` + db 表/CRUD + 协议端点（`/koreader` 独立前缀、不走 Bearer 中间件，同 OPDS 理由）+ 管理接口（`/api/koreader`、`/api/koreader/scan`、`/api/koreader/docs`）+ 设置页 `/settings/koreader`（开关 / 地址可复制 / 账号 / 扫描索引 + 文档表 / KOReader 填写指引）

### 验证 40/40 + 浏览器
- **partialMD5 用「可手工验算」的用例对照**（避免自证）：3000 字节 a 文件 = `md5(a*1024 + a*1024)`；空文件 = `md5(b'')`；300 字节文件 = `md5(b*44)`
  - ★ **第一版有一条用例写错了**：我用 `partial_md5(a*3000) != md5(a*2048)` 想验证「起点不是 0」——内容均匀时从 0 还是 256 采样读到的字节**完全一样**，断言恒假。改成**内容可区分**的构造（`X*256 + A*1024 + B*2816 + C*1024` → 期望 `md5(A*1024 + A*256 + B*768 + C*1024)`）才真正验证了起点 256

- **双向闭环**：PUT（DocFragment[5] + 0.375）→ NF 进度变 `(locator=4, percent=37.5)` → GET 回来 `percentage=0.375` + XPointer 回到第 5 段 + timestamp > 0；PDF 反向输出页码

### 教训（两条硬坑）
1. **`core/` 里的模块引用 `config` 要写 `from .. import config`**（config 在 `novelforge/` 顶层，不在 core/）。
   写错会让**整个服务起不来**（uvicorn import 失败），而 **`py_compile` 只查语法、不解析 import → 抓不到**。
   新模块加完后，要跑一次「真的 import 一遍」或直接起服务验证
2. **`.upper() != "epub"` 这种大小写自相矛盾的写法**：`library.books()` 的 format 本来就是大写 `EPUB`，
   写成与 `"epub"` 比 → 每本 EPUB 都被判成「非 EPUB」跳过。**只有端到端验证才暴露**
