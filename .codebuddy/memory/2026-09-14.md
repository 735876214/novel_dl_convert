## 代码审查与修复（novel_dl_convert / NovelForge，TXT→EPUB 工具）
对仓库做了冗余/死锁审查并修复 6 处（无经典循环等待死锁，主要风险是同步锁在 asyncio 事件循环线程长持导致服务假死）：

1. `novelforge/core/detect.py`：AI 分章原 `asyncio.run(detector.detect(text))` 在 async 路径（Web 下载/上传，uvicorn 事件循环线程）会抛 RuntimeError 被 except 吞掉→AI 兜底静默失效。改为调用 `ai_detect._run_in_thread(detector.detect(text))`（独立线程跑新 loop）。
2. `novelforge/server.py`：`mark_processed/mark_recent` 经 `await asyncio.to_thread(...)` 调用；`_log_dispatch` 改 async，`convert_path` 改 async。消除 watcher 后台线程持 `state` 锁转换时，事件循环线程在 mark 处被阻塞→整个 Web 服务假死。
3. `novelforge/core/watcher.py`：`FolderWatcher` 新增独立 `_scan_lock`（串行化扫描轮次，防并行重复处理）；原 `_lock` 只保护 `state` 字典短临界区，转换 I/O 移出锁。`stop()` join 超时放宽到 `max(interval+5, 30)`。
4. `novelforge/core/network.py`：删除从未使用的死代码 `self._lwp = httpx.CookieJar()`；`run_js` 改用 `asyncio.get_running_loop()`（消除弃用/非 loop 线程误用）。
5. `novelforge/sources/manager.py`：`search` 单源失败日志 `print` → `logging.getLogger(__name__).warning`。
6. `novelforge/core/metadata.py`：删除 `from_body` 中永不被管线消费的 `cover` 解析。

仍存在的非阻断项（未改）：同步转换不可被 `stop()` 中断（固有限制，已通过放宽 join 超时 + 缩小 state 锁范围缓解）。

## 本机 Docker 拉取镜像的网络问题与解法（重要）

解法（已实施）：在 `C:\Users\qingr\.docker\daemon.json` 加 `registry-mirrors`
（`https://docker.m.daocloud.io` / `https://docker.1ms.run` / `https://hub.rat.dev`），
执行 `docker desktop restart` 生效（`docker info` 已确认 Mirrors 加载成功）。
原 daemon.json 内容仅 `builder.gc` + `experimental`，已保留。

## 新增：输入目录自动监听 + 活动日志（需求：input 里 txt 自动转 epub，非 txt 导出到 output，全过程记日志）

新增模块：
- `novelforge/core/activity_log.py`：活动日志。字段 = 时间 / 文件名 / 操作（转换·添加·跳过）/ 成功或失败
  + 输出文件名、体积、耗时、来源（watcher / upload / api / download）。**双写** `activity.log`（可读文本）
  与 `activity.jsonl`（结构化，供 API）。目录默认 `LOG_DIR`（= `CONFIG_DIR/logs`），写不进时降级临时目录。
- `novelforge/core/watcher.py`：`FolderWatcher`。**轮询** input（不用 inotify：NAS 的 SMB/NFS 挂载事件不可靠）；
  `.txt` → `pipeline.convert_txt` 转 EPUB 落 output（记「转换」）；其它文件 `shutil.copy2` 原样导出（记「添加」）。

关键设计：
- **写入稳定判定**：连续 `stable_rounds` 次（每次间隔 `settle_seconds`）读到相同 size 才处理，避免拷贝一半就转。
- **状态持久化**：`CACHE_DIR/watcher_state.json` 存 `relpath -> {size, mtime, failed}`；
  指纹一致即跳过（重启不重复转换），文件被覆盖更新才重转。
- **失败重试**：同一文件失败累加 failed，达到 `max_retries`(3) 后记一次失败并跳过，避免坏文件反复刷日志。
- `mark_processed()` / `mark_recent()`：供上传 / 下载等内部流程登记，避免监听线程对已生成成品的文件重复转换。

接入点：
- `config.py`：新增 `LOG_DIR`、`watcher` / `logging` 默认配置；`ensure_dirs` 增加日志目录；
  `load_config` 支持 `AUTO_WATCH` / `WATCH_INTERVAL` 环境变量覆盖。
- `server.py`：FastAPI `lifespan` 启动/停止监听线程；新增 `/api/watcher`（状态）、
  `/api/watcher/start|stop`、`/api/scan`（立即扫描）、`/api/logs`（查询，支持 action/status/q）、
  `/api/logs/download`、`DELETE /api/logs`；`/convert`、`/convert-path`、下载任务、全部写日志。
- `cli.py`：新增 `watch`（常驻）/ `scan`（单次）/ `logs`（查看过滤）子命令。
- Web：新增「转换日志」标签页（监听状态卡 + 日志表，可筛选 / 自动刷新 / 下载 / 清空）。
- `docker-compose.yml` 加 `LOG_DIR` 与 `AUTO_WATCH`、`WATCH_INTERVAL` 注释项；版本号 → 0.5.0。

## 踩坑（同日）

- **`threading.Lock` 自锁**：`activity_log.log()` 持 `_lock` 后又调 `log_dir()`（内部再取同一把锁）→ 死锁。
  现象极坑：进程**静默挂死**，既无异常也无 traceback（SystemExit/死锁不走 excepthook），
  表现为「脚本卡在某一行、超时被杀、退出码 1、没有任何输出」。已改 `threading.RLock`。
  **教训：模块内多处共用一个锁且有嵌套调用时，一律用 RLock。**
- **本工作区 PowerShell 工具不回显 stdout**（`git status` 等返回空）—— 该沙箱限定，已过期。
  解决方式是命令输出重定向到文件（`| Out-File`）再读；Python 脚本自己写报告文件更稳。
  （在 CodeBuddy 环境下 PowerShell 正常回显，但多行输出仍可能被截断，拼成单行最稳。）
- **沙箱限制**：Python 进程往系统临时目录（`%TEMP%`）建目录/写文件会被杀（退出码 1、无输出）——
  该沙箱限定，已过期。当时测试脚本的临时目录要放在**工作区内**（如 `_test/_tmp`）。
- `recent()` 曾有**双重 reverse** bug：从 jsonl 回填时多 reverse 一次，导致返回顺序变成旧→新；
  现在统一「内存/文件都是旧→新，`reversed()` 后给 API」。
